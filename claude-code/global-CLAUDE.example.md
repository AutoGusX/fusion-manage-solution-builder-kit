## How I like you to work
- **Plan before building** on any non-trivial task: propose an approach, get a nod, then implement.
- **Specs and backlogs are the source of truth.** In a project, specs live in `specs/` and current work in `BACKLOG.md`. Read the relevant spec before implementing; update the backlog as work completes.
- **Verify before calling something done.** Drive the change end to end, don't just claim tests pass.
- Be concise. Give a recommendation, not an exhaustive menu of options.
- When something fails, say so plainly with the output. Don't paper over it.
- Before probing a Fusion Manage tenant, read the gotchas file. Never write to a tenant I haven't named as a sandbox without asking.
- Never commit tokens, tenant names, API captures or customer data.
